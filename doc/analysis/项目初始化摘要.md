# 项目初始化摘要

> 基于当前仓库 `workshop_zx` 分支代码梳理，便于新人上手与评审。

---

## 1. 系统定位与核心业务域

- **定位**：企业内部**福利积分商城**（后端 `pom.xml` 描述为「企业内部福利商城后端服务」）。员工使用**积分**兑换商品，管理员维护商品、订单与用户积分/状态。
- **核心业务域**：
  - **目录与商品**：分类、商品列表/详情、搜索与排序（积分价、库存、销量等字段）。
  - **交易闭环**：购物车 → 收货地址 → 下单扣积分 → 订单状态流转（含取消）；管理员可改订单状态。
  - **用户与资产**：用户资料、积分余额、**积分流水**（`PointsHistory`）。
  - **扩展行为**：收藏、浏览量/收藏数等统计字段（部分逻辑为简化实现，见下文风险）。

## 2. 主要角色与权限边界

| 角色 | 标识 | 典型能力 |
|------|------|----------|
| 普通用户 | `user` | 登录后访问商城、购物车、订单、个人资料、收藏、地址等；仅能操作**本人**数据（如订单详情会校验 `userId`）。 |
| 管理员 | `admin` | 除普通能力外，可访问 `/admin/**` 接口：全量商品 CRUD（软删）、全量订单与状态更新、用户列表、调整用户积分、启用/禁用用户、分类增改等。 |

**鉴权实现要点**：

- **JWT**：登录成功后签发 Token，请求头 `Authorization: Bearer <token>`；`AuthMiddleware` 全局 Filter 校验 Token，并将 `userId`、`username`、`role` 写入 `request` 属性。
- **匿名可访问**（无需 Token）：根路径 `/`、`/health`、`/auth/login`、**商品** `/products` 及子路径、**分类** `/categories` 及子路径。其余接口默认需登录。
- **管理员接口**：`/admin/**` 在各方法内判断 `role` 是否为 `admin`，非管理员返回 403。
- **前端路由**：`requiresAuth` 校验本地 `token`；`requiresAdmin` 校验 `localStorage` 中 `userInfo.role === 'admin'`（与后端 JWT 中的 `role` 应对齐）。

**初始化测试账号**（`DataInitializer`）：`user1`～`user3` 明文密码；`admin` / `admin123` 为 BCrypt。登录页亦展示上述账号（仅适合演示/开发环境）。

## 5. 项目启动方式、运行前提、已知工程风险

### 启动方式

**后端**（在 `backend` 目录）：

```bash
mvn spring-boot:run
```

或使用 IDE 运行 `com.example.mall.MallApplication`。启动后 API 根路径示例：`http://localhost:8080/api/`，健康检查：`http://localhost:8080/api/health`。

**前端**（在 `frontend` 目录）：

```bash
npm install
npm run dev
```

浏览器访问开发地址（一般为 `http://localhost:3000`）。生产构建：`npm run build`，`npm run preview` 预览；生产环境需自行配置反向代理或 `baseURL`，使 `/api` 指向真实后端。

### 运行前提

- **JDK 17**、**Maven 3.x**。
- **Node.js**（建议 LTS）与 npm，用于前端依赖与 Vite。
- 首次启动后端会在 SQLite 路径下创建/更新 `database/mall.db`；空库时 **`DataInitializer`** 会写入演示用户、分类与商品。

### 已知工程风险与注意点

1. **安全/配置**：`application.yml` 中 **JWT 密钥明文**、CORS 对来源较宽（`allowedOriginPattern("*")` 且 `allowCredentials(true)`），仅适合开发；生产应使用环境变量/密钥托管并收紧跨域。
2. **认证模型**：未使用完整 **Spring Security** 资源级配置，依赖自定义 Filter + 各接口手写角色判断；**商品/分类列表接口可无 Token 调用**，若业务要求「仅登录可见」，需调整 `AuthMiddleware` 白名单或网关策略。
3. **密码策略**：种子用户中部分为**明文密码**（`AuthService` 亦兼容明文校验），与管理员 BCrypt 混用——**严禁用于生产**。
4. **数据层**：**SQLite** 文件库，并发与运维能力有限；`ddl-auto: update` 在多人协作/生产环境可能带来 schema 漂移风险。
5. **数据一致性/实现完整性**：`ProductController` 中增加浏览量的逻辑**注释说明未落库**，可能导致统计不准。
6. **文档与代码不一致**：`HealthController` 的 `/test` 返回信息中写 **JDK 21**，与 `pom.xml` 的 **Java 17** 不一致，易误导运维/新人。
7. **前端 Token**：存 **localStorage**，需防范 XSS；无刷新 Token 机制（依赖 JWT 过期时间）。
8. **测试**：工程以手工与演示为主，`spring-boot-starter-test` 存在但**自动化测试覆盖情况需自行评估**。

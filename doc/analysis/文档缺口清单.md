| 缺失项 | 说明 |

## 3. 哪些缺口会影响后续测试设计与变更实施

### 3.1 对测试设计的影响

| 缺口 | 影响 |
|------|------|
| **无书面验收标准** | 用例无法对齐「必须/应该」，易与产品理解偏差；**回归范围不确定**。 |
| **订单状态无权威规则** | 无法定义「应通过/应拒绝」的边界用例（尤其管理员改状态与取消）。 |
| **无 OpenAPI** | 契约测试、Mock 服务器、前端类型生成**缺少自动化锚点**；接口变更需人工 diff。 |
| **无自动化测试基线** | 变更易引入回归；**技术文档 §16 测试矩阵**可用手工执行，但**无 CI 门禁**。 |
| **前后端行为未在需求层对齐** | 如下单未接前端，测试若只测 API 会漏**端到端**；若只测 UI 则与当前实现不一致。 |

### 3.2 对变更实施的影响

| 缺口 | 影响 |
|------|------|
| **README 仍偏简要 / 缺环境模板** | 新人 onboarding 与 CI 环境仍可能不一致。 |
| **`start.ps1` 与 `pom` Java 版本不一致** | 实施变更时**误判 JDK 要求**，构建或 CI 选型错误。 |
| **密钥与配置在仓库中** | 变更若涉及安全，**易误提交**；无环境隔离说明。 |
| **无 ADR** | 替换 SQLite、引入消息队列等**大重构缺少决策依据**，易反复争论。 |
| **OpenSpec 无落地 spec** | 若团队依赖 OpenSpec，**无 `openspec/specs` 与变更单**则提案与实现**无单一事实来源**。 |

### 3.3 建议优先级（实施顺序）

1. **充实根目录 [README.md](../../README.md)**：克隆、JDK/Maven/Node、启动前后端、访问地址、默认账号提示（注明演示用）；与 [doc/README.md](../README.md) 分工明确。  
2. **修正 `start.ps1` 与 `pom` 的 Java 版本表述**（或改为使用 `mvnw` 的 `toolchains`/文档说明）。  
3. **订单状态与管理员操作** 的**一页纸业务规则**（可与现有技术文档 §10 对齐后冻结一版）。  
4. **OpenAPI**（或至少维护与代码同步的 `api.md`）+ **错误码表** 单一来源。  
5. **最小自动化测试**（如 `OrderService` 核心路径）+ **CI 骨架**（可选）。  
6. **OpenSpec**：对下一重大功能创建 `openspec change`，把 spec 与 tasks 纳入评审。

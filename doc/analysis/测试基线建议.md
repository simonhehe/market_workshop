# 测试基线建议

> 从**测试与质量**视角，结合当前仓库实现（后端 Spring Boot + SQLite + JWT，前端 Vue3 + Vite）及已知行为与风险，给出 **smoke 主链路**、**白盒切入点**、**高风险场景**与**应优先补齐的测试资产**。  
> 与 **[单链路基线分析_技术.md](单链路基线分析_技术.md)** §16 测试矩阵、[文档缺口清单.md](文档缺口清单.md) 可交叉阅读。

---

## 1. 当前最适合做 Smoke 的主链路

**目标**：用最短路径验证「服务活着 → 能鉴权 → 核心业务可读」，适合 **CI 每日构建** 或 **发布前门禁**（建议全部走 **HTTP API**，不依赖前端页面，因购物车→下单 UI 未闭环）。

### 1.1 推荐 Smoke A：最小存活 + 匿名可读（约 3 步）

| 顺序 | 动作 | 断言要点 |
|------|------|----------|
| 1 | `GET /api/health` | HTTP 200，body 含成功语义（`ApiResponse`） |
| 2 | `GET /api/categories` 或 `GET /api/products` | HTTP 200，返回列表（白名单接口） |
| 3 | （可选）`GET /api/` 根信息 | HTTP 200 |

**价值**：不依赖账号与数据库种子即可验证进程与路由；适合容器/新环境**首跑**。

### 1.2 推荐 Smoke B：登录 + 用户读路径（约 5 步）

| 顺序 | 动作 | 断言要点 |
|------|------|----------|
| 1 | `POST /api/auth/login`（种子用户，如 `user1`/`password1`） | 200，`data.token` 非空 |
| 2 | `GET /api/cart` 带 `Authorization: Bearer` | 200（允许空车） |
| 3 | `GET /api/orders`（可选 `?status=pending` 等合法值） | 200，数组 |
| 4 | `GET /api/user/info` 或等价用户信息接口（以 `UserController` 为准） | 200 |
| 5 | `GET /api/points/history` | 200 |

**价值**：验证 **JWT 过滤器**、用户上下文与**用户域只读接口**整体可用。

### 1.3 推荐 Smoke C：订单链全 API 闭环（深度 smoke，依赖种子数据）

| 顺序 | 动作 | 断言要点 |
|------|------|----------|
| 1 | 用户登录，取 token | — |
| 2 | `POST /api/cart` 加购可兑换商品 | 200，购物车有行且 `isSelected` 默认 1 |
| 3 | （可选）`GET /api/addresses`，或 `POST /api/addresses` 建地址 | 取得合法 `addressId` |
| 4 | `POST /api/orders`，body 含 `addressId`（可选）、`remark` | 200，`data.status` 为 `pending`；积分减少、库存减少 |
| 5 | `GET /api/orders/{id}` | 明细与订单一致 |
| 6 | `PUT /api/orders/{id}/cancel` | 200，状态 `cancelled`，积分与库存恢复（与 `OrderService` 语义一致） |

**价值**：覆盖**下单 + 取消**的财务与库存副作用，是现阶段**最有业务代表性**的 smoke。  
**注意**：需保证种子用户积分与商品库存足够；建议在测试环境使用**固定种子**或**测试前置 SQL**。

**不建议**把「纯前端从购物车点结算」作为 smoke 主链路：当前 **`/orders/create` 路由问题**会导致 E2E 不稳定（见 [单链路基线分析_技术.md](单链路基线分析_技术.md) §14）。

### 1.4 推荐 Smoke D：确认收货 + 列表筛选（API）

| 顺序 | 动作 | 断言要点 |
|------|------|----------|
| 1 | （前置）存在本人订单且 `status=shipped`（可由管理员 `PUT /api/admin/orders/{id}/status` 调整种子订单） | — |
| 2 | `PUT /api/orders/{id}/confirm-receipt` | 200，`data.status` 为 `completed`；积分与库存与确认前一致 |
| 3 | 再次 `PUT /api/orders/{id}/confirm-receipt` | 200，幂等，`status` 仍为 `completed` |
| 4 | `GET /api/orders?status=shipped` | 200，结果中不含刚已完成的订单（若仅一单测完） |
| 5 | `GET /api/orders?status=not_a_status` | 400，`error.code` 为 `ORDER_004` |

**价值**：覆盖 **ORDER_003/ORDER_004** 与用户侧新契约；可与 Smoke B/C 串跑。

## 2. 当前最适合做 White-box（白盒）的代码点

白盒应优先落在**业务不变量集中、分支多、且与资金/库存相关**的类；便于 **JUnit 5** 在内存库或 mock 上快速执行。

### 2.1 最高优先级（单元 / 小集成）

| 代码位置 | 测什么 |
|----------|--------|
| **`OrderService.createOrder`** | 无选中购物车行、库存不足、积分不足、地址不存在、`pending` 创建、扣积分、写流水、删购物车行、扣库存；**事务回滚**（可通过注入异常或 mock repository 验证）。 |
| **`OrderService.cancelOrder`** | 非本人、非 `pending` 拒绝；成功路径退积分、refund 流水、还库存、销量回退、`cancelled`。 |
| **`OrderService.confirmReceipt`** | 非本人、非 `shipped` 拒绝；`completed` 幂等；成功仅改 `status`。 |
| **`OrderService.getUserOrders(..., status)`** | 空白参数全量；非法 `status` → `IllegalArgumentException` / `ORDER_004`。 |
| **`UserService.updatePoints`** | 积分加减后余额；可补充「扣成负数是否允许」的**规格化**测试（当前实现无下限校验，测试即文档）。 |
| **`CartService.addToCart` / `updateQuantity`** | 加购超库存、合并行后总数量与库存关系（已知**合并后未二次校验**的缺陷可固化为失败用例或变更单）。 |

### 2.2 次优先级（Web 层 / 安全）

| 代码位置 | 测什么 |
|----------|--------|
| **`OrderController`** | `getOrderDetail` / `cancelOrder` 的 **userId 与 order.userId** 一致性；路径参数类型错误。 |
| **`AdminController`**（订单相关） | `role != admin` → 403；`PUT .../status` 成功路径。 |
| **`AuthMiddleware`** | 白名单路径（`/products`、`/auth/login` 等）不带 token 仍 200；受保护路径无 token → 401。 |

### 2.3 不建议过早深白盒的点

- **纯 CRUD 且无副作用**的 Controller：收益低，可让位给 API smoke。  
- **前端组件**：在缺少 E2E 基线前，优先 **API 层** 锁定行为。

## 3. 当前最可能出问题的边界 / 状态 / 权限场景

以下为**缺陷高发区**，建议进入**回归集**或**探索性测试清单**（与 §16 矩阵对应扩展）。

### 3.1 边界与数据

| 场景 | 为何高风险 |
|------|----------------|
| 购物车合并后数量 **>** 实时库存 | `addToCart` 合并路径未再校验总库存；下单时才失败，体验与数据不一致。 |
| 并发两单抢同一 SKU | 无乐观锁/条件更新，可能 **超卖** 或负库存（视 DB 约束）。 |
| `addressId` 指向**他人地址** | `createOrder` 未校验归属，存在错寄与安全争议。 |
| 商品已 `inactive` / 软删 | `createOrder` 若仍 `findById` 成功，可能卖出「不应卖」商品。 |

### 3.2 状态与角色

| 场景 | 为何高风险 |
|------|----------------|
| 用户取消 **非 pending** | 应稳定失败；若前端误展示按钮需单测/组件测约束。 |
| 管理员将订单改为 **`cancelled`** | **不退积分、不还库存**，与用户取消语义不一致，易引发资损争议。 |
| 管理员写入 **任意 status 字符串** | 无状态机校验，报表与前端下拉选项易错乱。 |

### 3.3 权限与安全

| 场景 | 为何高风险 |
|------|----------------|
| `PUT/DELETE /api/cart/{id}` **非本人 cartId** | Controller **未校验 userId**，存在水平越权（应用测试应显式断言「当前行为」并挂变更单修复）。 |
| Token 过期 / 伪造 | JWT 密钥在配置中；集成环境应使用**独立测试密钥**。 |

### 3.4 前后端一致性

| 场景 | 为何高风险 |
|------|----------------|
| 用户从购物车发起「结算」 | 当前路由 **不能** 完成下单；任何依赖 UI 的 smoke 会误报失败。 |

## 4. 哪些测试资产应先补为基线

结合仓库**当前无 `*Test.java` / 无前端 spec**的现状，建议按以下顺序沉淀资产（先**自动化可重复**，再扩展覆盖）。

### 4.1 第一优先（1～2 天内可落地）

| 资产 | 内容 | 作用 |
|------|------|------|
| **`src/test/resources/application-test.yml`** | 独立 SQLite 文件或内存库、`jwt.secret` 测试值、`ddl-auto` 可控 | 测试与开发库隔离，避免踩 `mall.db`。 |
| **`OrderServiceTest`（`@ExtendWith(MockitoExtension.class)` 或 `@DataJpaTest`+内存库）** | 覆盖 `createOrder` / `cancelOrder` 主路径与关键异常 | **白盒基线**，防回归最强。 |
| **Smoke 脚本** | `curl`/PowerShell 或 **REST Assured** 小类：Health + Login + Products | CI 一键绿/红；无需启动浏览器。 |

### 4.2 第二优先（短期迭代）

| 资产 | 内容 | 作用 |
|------|------|------|
| **`@SpringBootTest` + `MockMvc`** | `OrderController`、`CartController`（含越权用例） | 验证 HTTP 与序列化、权限属性注入。 |
| **固定测试数据构建器** | Builder/Fixture 创建 User/Product/Cart，避免复制种子 SQL | 降低用例脆弱性。 |
| **错误码断言** | 对 `ORDER_*`、`CART_*`、`AUTH_004` 做稳定断言 | 与接口文档对齐，防文案乱改。 |

### 4.3 第三优先（质量成熟后）

| 资产 | 内容 | 作用 |
|------|------|------|
| **Playwright / Cypress**（任选） | 登录 + 商品列表（**不要**依赖未完成下单页作为主门禁） | UI smoke；待下单页修复后再加长链路。 |
| **并发测试**（JUnit + 多线程或 Gatling） | 同 SKU 并行下单 | 验证超卖；需明确是否纳入发布门禁（易 flaky）。 |
| **OpenAPI 生成 + 契约测试** | 引入 springdoc 后 | 长期减少前后端契约漂移。 |

### 4.4 CI 基线建议

- **最小 CI**：`mvn -q test`（有测试后）+ **Smoke A** HTTP 探活。  
- **合并前**：至少 **Smoke B** + **`OrderServiceTest` 全绿**。  
- 前端：**`npm run build`** 作为静态基线；E2E 待路由修复后再接。

---

## 5. 小结

| 类型 | 建议 |
|------|------|
| **Smoke 主链路** | 以 **API** 为主：**存活 → 登录 → 读业务**（B）；有精力再上 **下单+取消**（C）。 |
| **White-box 首选** | **`OrderService`**，其次 **`CartService`**、**`OrderController`**、**`AuthMiddleware`**。 |
| **高风险场景** | 库存/并发、地址归属、购物车越权、管理员状态与取消语义、UI 下单缺口。 |
| **先补资产** | **测试配置** + **`OrderService` 单元/小集成测试** + **可脚本化 smoke**；再扩 **MockMvc** 与 **CI**。 |

# 测试基线建议

> 从**测试 / 质量**视角：Smoke 主链路、白盒切入点、高风险边界与权限场景、应优先补齐的测试资产。  
> **现状**：白盒 JUnit 位于仓库根目录 **`test/backend/java`**（与 `backend/src` 分离，供测试团队维护）；`backend/pom.xml` 已配置 `testSourceDirectory` 指向该路径，执行 **`cd backend && mvn test`** 即可。冒烟脚本见 **`test/smoke/`**；UI 自动化占位 **`test/ui/`**。

---

## 1. 当前最适合做 Smoke 的主链路

**目标**：用最短路径证明「服务活着 + 前后端可联调 + 核心读路径可用」，**不依赖**未实现的下单页（如 `/orders/create`）。

### 1.1 建议 Smoke 序列（后端可直接 curl / Postman）

| 顺序 | 动作 | 说明 |
|------|------|------|
| S1 | `GET /api/health`（或 `GET /api/`） | 进程与上下文路径正确 |
| S2 | `GET /api/categories` | 白名单，无 JWT |
| S3 | `GET /api/products` 或列表接口（以实际 `ProductController` 为准） | 白名单，无 JWT |
| S4 | `POST /api/auth/login` body `{"username":"user1","password":"password1"}` | 拿到 `token` |
| S5 | `GET /api/cart` Header `Authorization: Bearer <token>` | JWT 与 Filter 生效 |
| S6 | （可选）`GET /api/orders` | 用户订单列表 |
| S7 | （可选）管理员 `POST /api/auth/login` `admin/admin123` → `GET /api/admin/orders` | 管理端只读 |

**说明**：创建订单 `POST /api/orders` 依赖购物车选中商品与积分，**步骤多、数据依赖强**，更适合放在 **回归 / 集成** 而非每日最短 Smoke；若要做「写路径」Smoke，可单独定义为 **S8**（见 §4）。

### 1.2 前端 Smoke（人工或 Playwright 极简）

登录 → 首页/商品列表能打开 → 购物车页能打开（不要求结算成功）。

## 2. 当前最适合做 White-box 的代码点

白盒应优先覆盖 **业务复杂度高、副作用多、分支密** 且 **与资金类数据（积分/库存）相关** 的单元 / 切片测试。

| 优先级 | 类 / 方法 | 理由 |
|--------|-----------|------|
| P0 | `OrderService.createOrder` | 购物车筛选、库存、积分、地址、订单/明细落库、扣减、流水、删购物车；**分支与异常路径多** |
| P0 | `OrderService.cancelOrder` | 权限、状态 `pending`、退款积分、流水、库存回补、销量回冲 |
| P1 | `AuthService.login`（及密码校验分支） | 明文/BCrypt 用户与管理员路径差异 |
| P1 | `JwtUtil` | 签发、解析、`userId`/`role` 声明；与 Filter 行为一致 |
| P1 | `CartService.addToCart` / `updateQuantity` | 库存校验、合并行、数量为 0 删除 |
| P2 | `AdminService.updateOrderStatus` | 当前无校验，**适合用测试固化「现状」或驱动重构** |
| P2 | `UserService.updatePoints` | 积分加减与边界（负数是否允许等） |

**不建议**一开始全量白盒 `Controller`（薄层）；优先 **Service + 少量 Repository 切片**（`@DataJpaTest` 或内存 H2/SQLite 测试库）。

## 3. 当前最可能出问题的边界 / 状态 / 权限场景

### 3.1 权限与身份

| 场景 | 风险 |
|------|------|
| 无 token 访问受保护资源 | 应 401；与白名单路径混淆则**安全基线失败** |
| 普通用户访问 `/admin/*` | 应 403 |
| **购物车 `PUT/DELETE /cart/{id}` 未校验 `cart.user_id`** | **水平越权（IDOR）**：猜中 id 可改删他人购物车行 |
| **下单时 `addressId` 未校验归属** | 订单可挂到他人地址快照 |
| 用户读他人 `GET /orders/{id}` | 实现中已比对 `userId`，需回归防回归 |

### 3.2 状态与业务规则

| 场景 | 风险 |
|------|------|
| 非 `pending` 取消订单 | 应失败；防误退款 |
| 管理员 `PUT /admin/orders/{id}/status` 任意字符串 | **数据脏乱**；与前端下拉不一致 |
| `cancelled` 再被改为 `processing` | 库存/积分已处理，**与实现不一致** |
| 商品 `status`、软删与下单 | `OrderService` 未校验，**下架仍可下单**（若库存仍为正） |

### 3.3 数据与并发边界

| 场景 | 风险 |
|------|------|
| 库存 = 1，两单并发 | **超卖** |
| 积分边界：刚好等于、差 1 | 边界值 |
| 购物车 `isSelected` 全 0 | 应拒绝下单 |
| `GET /orders/{id}` 与 `deleted_at` | 软删订单是否仍可读（实现差异） |

### 3.4 前后端一致性

| 场景 | 风险 |
|------|------|
| 结算跳转 `/orders/create` **路由不存在** | **用户侧核心路径断裂** |
| 购物车勾选无后端 API | UI 与「部分结算」不一致 |

## 4. 哪些测试资产应先补为基线

按 **性价比**：先能跑起来、再覆盖高风险、再扩展契约与 E2E。

| 序号 | 资产 | 内容 | 目的 |
|------|------|------|------|
| T1 | **Smoke 脚本** | `curl`/Shell 或 `newman` 集合：§1.1 序列 + 可选建单 | 每日/CI 第一步门禁 |
| T2 | **后端单元 / 切片测试** | JUnit 5 + Mockito：`OrderService` 核心路径 mock Repository；或对 SQLite 使用 **独立测试库** 做 `@SpringBootTest` 窄场景 | **防回归**最复杂业务 |
| T3 | **API 契约快照或契约测试** | 至少固定 `ApiResponse` 形状 + 主路径 HTTP 状态码 | 前后端变更可检 |
| T4 | **安全回归用例集** | IDOR（购物车 id）、地址盗用、admin 非管理员 | 与 §3.1 对齐，**修复前后对照** |
| T5 | **测试数据种子** | 与 `DataInitializer` 对齐的 fixture（用户、商品库存、积分） | 集成测试可重复 |
| T6 | **（可选）前端 E2E** | Playwright/Cypress：登录 → 列表 → 购物车 | UI Smoke；**在下单页修复后再加下单** |

**不推荐**一上来：全链路压测、全量 E2E 覆盖所有页面——在契约与 Service 测试未稳时**维护成本高**。

### 4.1 与「文档缺口」的衔接

- `doc/单链路基线分析_技术.md` §5.8 **测试矩阵 H1～H11** 可直接映射为 **集成测试用例 ID**。  
- `doc/文档缺口清单.md` 中接口与状态无单一事实来源时，测试应 **以当前代码行为为基线并标注「应然待产品确认」**，避免无效争论。

## 5. 小结

| 维度 | 建议 |
|------|------|
| **Smoke** | 健康检查 → 公开分类/商品 → 登录 → 带 JWT 读购物车/订单（+ 可选管理端只读） |
| **White-box 首选** | `OrderService` 创建/取消、`AuthService`/`JwtUtil`、`CartService` |
| **最高风险** | 购物车/地址 IDOR、并发库存、管理员状态任意写、前端结算路由缺失 |
| **先补基线** | Smoke 自动化 + `OrderService` 测试 + 安全回归清单 + 固定测试数据 |

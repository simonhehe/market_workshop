# 购物车勾选与归属

## ADDED Requirements

### Requirement: 勾选状态必须持久化

用户必须能够对本人购物车项设置选中状态，且状态持久化到数据库；合计与结算范围只统计 `isSelected=1` 的条目。

#### 场景：取消勾选后刷新
- **当** 用户将购物车中一件商品设为 `isSelected=0` 并刷新页面
- **则** 该商品保持未选中，购物车合计只包含其余选中项

#### 场景：加购默认选中
- **当** 用户首次加购某商品
- **则** 新建购物车项 `isSelected=1`

### Requirement: 勾选与数量修改必须校验归属

任何购物车项修改必须校验 `userId` 归属；越权操作不得改变数据。

#### 场景：修改他人购物车项
- **当** 用户对不属于本人的购物车项执行勾选、改数量或删除
- **则** 请求被拒绝并返回 `CART_ITEM_FORBIDDEN`，目标数据不变

### Requirement: 加购与改数量必须按库存约束

加购后的累计数量、修改后的数量均不得超过当前库存。

#### 场景：累计加购超库存
- **给定** 商品库存 3，购物车已有 2 件
- **当** 用户再加购 2 件
- **则** 请求被拒绝并返回 `STOCK_INSUFFICIENT`，购物车数量保持 2

#### 场景：改数量超库存
- **给定** 商品库存 5，购物车数量 2
- **当** 用户把数量改为 6
- **则** 请求被拒绝并返回 `STOCK_INSUFFICIENT`

### Requirement: 未选中商品时不得进入结算

前端结算入口必须阻止空选中项跳转。

#### 场景：全部未选中点击结算
- **给定** 购物车所有条目 `isSelected=0`
- **当** 用户点击「结算」
- **则** 停留购物车并提示「请先选择要兑换的商品」，不进入 `/orders/create`

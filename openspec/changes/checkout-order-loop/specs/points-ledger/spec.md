# 积分流水与对账

## ADDED Requirements

### Requirement: 积分流水余额必须准确

每次积分变动写入 `PointsHistory` 时，`balanceAfter` 必须等于本次变动后的真实余额；spend 与 refund 均适用。

#### 场景：下单消费
- **给定** 用户余额 35000，订单应付 30200
- **当** 下单成功
- **则** 用户余额为 4800，spend 流水 `balanceAfter=4800`

#### 场景：取消退款
- **给定** 上述订单为 pending
- **当** 取消成功
- **则** 用户余额恢复 35000，refund 流水 `balanceAfter=35000`

### Requirement: 下单与取消必须可对账

订单、用户余额、流水与库存必须保持可验证的一致关系。

#### 场景：下单对账
- **当** 下单成功
- **则** `User.points` 等于最新流水 `balanceAfter`，变动差额等于订单 `totalPoints`

#### 场景：取消对账
- **当** 取消成功
- **则** 用户余额与商品库存恢复到下单前，refund 流水金额等于订单 `totalPoints`

### Requirement: 失败不得留下流水或扣减

任何校验失败或事务异常必须整体回滚，不得留下订单、流水、积分或库存变更。

#### 场景：校验失败
- **当** 下单因任一业务校验失败
- **则** 无新订单、无新流水、积分与库存不变

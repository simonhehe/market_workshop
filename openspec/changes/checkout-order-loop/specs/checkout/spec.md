# 结算页

## ADDED Requirements

### Requirement: 结算页必须展示选中商品与合计

`/orders/create` 必须要求登录，加载当前用户地址、选中购物车项与商品信息，展示名称、单价、数量、小计、件数、商品合计、运费 0、应付积分、当前积分与下单后余额；不得预选地址。

#### 场景：进入结算页
- **给定** 购物车存在选中商品
- **当** 用户点击结算
- **则** 进入 `/orders/create`，展示选中商品、数量与合计，地址区列出 mock 地址且无默认选中

#### 场景：无选中项直接访问
- **当** 用户直接访问 `/orders/create` 且购物车无选中项
- **则** 重定向回 `/cart` 并提示先选择商品

### Requirement: 地址必须显式选择

地址选择必须由用户点击产生；未选择地址时提交必须被前端拦截且不发送请求。

#### 场景：未选地址提交
- **当** 用户未选择地址点击「提交订单」
- **则** 显示「请选择收货地址后再提交订单」，不调用 `POST /api/orders`

#### 场景：选择地址
- **当** 用户选择第二条地址
- **则** 地址卡片显示选中态，底部寄送信息更新，积分合计不变

### Requirement: 数量与合计必须联动并受库存限制

数量步进范围为 `1..stock`；修改数量后小计、合计、应付与下单后余额必须同步更新。

#### 场景：增加数量
- **给定** 某商品数量 2、单价 20 积分
- **当** 用户增加到 3
- **则** 小计变为 60，合计与应付同步增加；达到库存后「+」不再生效

### Requirement: 提交必须防重复并处理错误

提交中必须禁用按钮且只发一次请求；接口失败必须根据业务错误键展示可重试的错误，库存不足需标记商品行；成功必须展示服务端订单号、实付积分与「待处理」状态。

#### 场景：重复点击
- **当** 请求未返回时连续点击提交
- **则** 仅发出一次请求

#### 场景：库存不足
- **给定** 某商品仅剩 1 件、结算数量 2
- **当** 提交或接口返回 `STOCK_INSUFFICIENT`
- **则** 展示全局错误并标记该商品行

#### 场景：下单成功
- **当** 接口返回成功
- **则** 展示服务端 `orderNo`、`totalPoints`、状态「待处理」，并提供查看订单入口
